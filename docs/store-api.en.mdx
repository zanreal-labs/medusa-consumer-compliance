title: Store API

All routes need the publishable API key header, like every `/store` route, and
answer only for published products in the key's sales channels.

The read routes for a product page sit under `/store/products/:id/...`, so a
deployment that only exposes `GET /store/products*` publicly needs no ingress
change for them. The withdrawal routes are `POST`s under
`/store/consumer-compliance/` and do need to be reachable.

## Product compliance

## Variants in bulk

`GET /store/consumer-compliance/variants?ids=variant_1,variant_2&region_id=...`

Up to 100 ids, for listing pages. Returns `{ "variants": [...] }` with the same
variant objects as above. Ids that are not visible to the key are dropped.

`GET /store/consumer-compliance/variants/:id/omnibus?region_id=...`

One variant's `omnibus` block.

Both accept `reduction_started_at=ISO date` to evaluate a reduction that is not a
price list, such as a discount code campaign started at that moment.

## Withdrawal

All three routes accept a logged-in customer (session or bearer token) and work
for guests.

`POST /store/consumer-compliance/withdrawals/lookup`

```json
{ "display_id": "1042", "email": "jan@example.com" }
```

A logged-in customer may send `{ "order_id": "order_..." }` alone. Returns the
order (`id`, `display_id`, `placed_at`, `canceled`) and `assessment`: per item
`eligible`, `excluded_reason`, `basis` (`delivery`, `contract_conclusion`,
`awaiting_delivery`), `deadline_at`, `within_period`, plus the order-level
`deadline_at`, `right_of_withdrawal` (`applies`, `excluded_digital_consent`,
`none_eligible`), `legal_basis` (Polish and English text, set for
`excluded_digital_consent`), `digital_consent_at` and `digital_consent_missing`
(see the digital-only section of [Withdrawal](./withdrawal.en.mdx)). Mismatch and unknown order both give 404.

`POST /store/consumer-compliance/withdrawals`

```json
{
  "display_id": "1042",
  "email": "jan@example.com",
  "customer_name": "Jan Kowalski",
  "contact_email": "jan@example.com",
  "items": [{ "line_item_id": "ordli_...", "quantity": 1 }],
  "statement": "optional, the default wording is used when omitted",
  "reason": "optional, never required",
  "locale": "pl"
}
```

Omit `items` to withdraw from every eligible item. `201` with
`{ "withdrawal": {...}, "confirmation_token": "..." }`. The withdrawal is
`pending_confirmation`; nothing is submitted yet. Errors: excluded item, quantity
above the ordered one, canceled order, or (with `rejectOutsidePeriod`) a period
that has ended.

`POST /store/consumer-compliance/withdrawals/:id/confirm`

```json
{ "token": "..." }
```

Submits the statement: `status: "confirmed"`, `submitted_at` set, acknowledgement
sent (`acknowledgement_sent_at`). A wrong token, an unknown id and an already
confirmed request all answer 404. An expired request answers 400 and must be
started again.

`GET /store/consumer-compliance/withdrawals` (logged-in customer only)

The customer's submitted withdrawals.

The public withdrawal object never contains the token hash, the assessment
internals or the trader's notes.
